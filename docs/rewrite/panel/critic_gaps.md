7. **[A — major] The two-band id scheme provably diverges from legacy node-id layout on every multi-stage bundle.** Legacy per-rank id space is: [per-stage Kahn main ops (Step 10)] ++ [ALL send/recv nodes appended afterwards (Step 11)], then only *control* sends/recvs are renumbered to the front — so **data** SENDs/RECVs sit at the *end* of the trace (lowest priority). Since ids are scheduling priorities, this shifts wall seconds on every pp>1 flattened/hier spec; R4's "dominant case: orders coincide on all current specs" is structurally false, and the "legacy-compatible sort key" fallback — which would in fact be the required default — is unspecified.
