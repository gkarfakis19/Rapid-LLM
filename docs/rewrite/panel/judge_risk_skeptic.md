# Judgment: RAPID-LLM AstraSim rewrite designs

Verification notes: I read `docs/rewrite/CONTEXT.md` and checked disputed claims against `/app/nanocad/projects/ispass_deepflow/deepflow_astra_dev_rewrite/Rapid-LLM/{simulate_train_graph.py, llm_execution.py, astrasim_lib/executor.py, astrasim_lib/gmap.py, train_timing.py, memory_estimation.py, simulate_inference_graph.py, equiv/configs.py, equiv/canonical.py, tests/golden_equiv/}`. Findings below cite lines.

## Cross-checked facts that frame the judgment

- Per-stage Kahn is keyed by `op_id` with `itertools.count` tie counters and **excludes cross-stage deps** (executor.py:1272–1294, 1302–1312). All three designs describe this correctly.
- p2p tags = `edge.op_id`, fallback counter from 1e6 (executor.py:1405–1420). Control classification is `size == 0 OR comm_type != PIPELINE` ⇒ 1-byte `_send_control` (executor.py:1440–1445).
- Control renumber moves control sends AND recvs to front, stable (executor.py:368–429). TP gids allocated **sorted-label, sorted-token**, base 1000, member-dedup (executor.py:1579–1590). dp skip rule: `dp_count <= 1 and task not in tp_collective_labels` (executor.py:1602).
- Flattener quirks verified: `rank_tails[0]`-only DP attach (llm_execution.py:804), `"bwd" in name` ±par_degree ZeRO-3 offset HACK and `int(base_bytes)` un-divided (llm_execution.py:477–493), op_id counter's first value is 1 (llm_execution.py:971–973). Flattener consumes only `transformer_cfg`/attrs/`comm_metadata` from the transformer graph, not its node structure (llm_execution.py:352–366, 914) — so A's "shim attribute carrier" is feasible.
- Same-stage layer transitions are zero-byte, zero-duration PIPELINE `Edge`s (simulate_train_graph.py:941–944); `local_comp_time` forced to 0 (simulate_train_graph.py:286–291).
- Canonicalizer ignores names, ids, tags, group ids (equiv/canonical.py:26–27) — so gate 3 (exact wall seconds) is the only gate that observes node-id order, and it observes it only as an opaque number. This is the central migration trap all three designs orbit.
- Golden matrix: hybrid goldens store transformer bundles under `hier/fwd` etc. (verified in `tests/golden_equiv/train_hybrid_dp2tp2cp1pp2mb2sp1_moe_ep2.json`), so A's "every hier/* bundle" phrasing at Stage 2 is right. **Memory is not captured in any golden** (no memory fields in `equiv/` or golden JSONs).

## Concrete factual errors

**Design A**
1. Stage 3a / R15 claim that memory replay is "verified by gate (4) end-to-end outputs" is **wrong**: memory peaks appear nowhere in the golden capture (checked `equiv/runner.py`, `equiv/capture.py`, golden JSON schema — only phase_times/total_time/astra_times/bundles/dlsim_ok). Gate 4 pins times only; A's memory migration is guarded only by its own smoke test.
2. "other groups: counter from 1000 in first-instantiation order… same id scheme retained anyway to keep artifacts diffable" — legacy allocates gids in **sorted-label/sorted-token pre-pass order** (executor.py:1579–1590), not first-instantiation order. Canonical-invisible, but the diffability claim fails.
3. Emitter control rule stated as `size_bytes == 0` ⇒ control; legacy is `size==0 OR comm_type != PIPELINE` (executor.py:1440). Representable via CTRL_DEP only if builders zero out every non-PIPELINE cross-stage transfer (e.g. ZeRO-3 cross-device attachments in the golden-covered `zero3` flattened specs) — unstated, and R2 doesn't cover it.
4. R1's "block chains are per-rank serial, so the DAG is forced" overclaims: MoE block programs branch at a2a/join/residual (A itself lists this in R11).

**Design B**
1. Risk 15's "no synthetic optimize_2dmap config… **none in the golden matrix, so no gate exposure**" is **flatly wrong**: `train:flattened:dp1_tp4_cp1_pp1_mb1:mesh2d_gmap` sets `optimize_2dmap: True` (equiv/configs.py:286–305) and is fully gate-covered. SCOTCH permutation parity is gate-exposed exactly at B's overloaded S2.
2. Minor: "feed in sid order (== legacy per-stage op order)" — legacy records collectives during `edge_stage` DFS-attribution iteration (executor.py:1171–1199), i.e. object-discovery order, not per-stage order. B's CSR parity test would catch it, but B planned that test on a synthetic config only (per error 1).
Everything else in B checked out, including obscure claims (flattener counter starts at 1; same-stage zero-byte PIPELINE edges; dp<=1-and-not-tp-labeled skip; label-sorted gid interning; ZeRO-3 un-divided bytes).

**Design C**
1. "the extractors are used for other flows and die at S5" is **wrong**: `extract_forward_graph`/`extract_backward_graph` have **zero call sites** repo-wide (grep confirms; hybrid/hier get direction-scoped graphs from `construct_transformer_graph(direction=...)`, train_timing.py:4987–4990). They are dead code; C's risk item R12 ("extract_*_graph inclusion rules" as a gate-relevant divergence surface) is a phantom risk.
2. Minor internal inconsistency: §3.1 Pass 2 classifies controls by `size==0` while R3 correctly states the `size==0 or non-PIPELINE` legacy rule; reconcilable only if lowering zeroes non-PIPELINE transfers (unstated).
C otherwise nailed the obscurest quirks: 1e6 fallback tag counter, collective-discovered stages extending `stage_to_ranks` with pre-extension `num_stages` (executor.py:1256–1261), `itertools.count` Kahn tie sequence, `local_comp_time` zeroing, `rank_tails[0]` DP attach.

## Ranked verdict (implementation-risk skeptic)

**1. Design B (schedule-first).** It is the only design that treats the id-order golden trap as a design input rather than a hope: `sid` is the semantic spine, `legacy` id policy re-runs the converter's own ordering algorithm over reproduced `prio`s, and the always-on per-group order postcondition converts the historical silent deadlock into a loud emission failure on every bundle, forever. Its two real weaknesses are fixable without redesign: split S2 (flattened ET, memory probe, evaluator machinery should be three landings), and correct the gmap risk assessment — the `mesh2d_gmap` golden means SCOTCH CSR parity must be proven against the real spec, not a synthetic one, before the flattened cutover.

**2. Design C (strangler).** Highest probability of landing all stages green — lowering-from-identical-inputs plus graph-level op_id-sequence differentials is the strongest verification story here, and C demonstrated the deepest command of the legacy quirks. But it buys safety by deferring the whole point: constraint 2's by-construction property doesn't exist until S6/S7, the group-order guarantee is a warning plus dlsim until then, and the end state has no schedule abstraction and no interleaved-PP story. It is the design most likely to ship and least worth shipping.

**3. Design A (ir-first).** The best end state and the best correctness argument, attached to the riskiest middle. Stage 3b demands exact wall-second equality from a from-scratch schedule/builder/emitter stack whose only id-order verification is the wall seconds themselves — the worst possible debugging loop — and its R4 fallback (a legacy-compatible sort key in `et_emit`) is precisely the ugly golden-forced compromise the design's purity claims deny. Its safety-net accounting also contains the one error that would bite silently (memory is not gate-protected). As a target architecture it wins; as a migration it is the one I'd expect to stall at 3b or quietly regen goldens.

## Strongest idea worth stealing from each

- **From A:** coarse and fine programs as two granularities of *one builder family over one shared schedule module* — flattening stops being a graph rewrite entirely, which kills the flattener bug class (name dispatch, sibling scans, ±par_degree offsets) at the root rather than reproducing it carefully. (Honorable mention: `OpKey` as stable semantic identity for retime/memory/fault write-back.)
- **From B:** the always-on emission postcondition asserting every communicator member's per-group collective sequence is identical — cheap, policy-independent, and it permanently converts the contract's silent-deadlock mode into a loud pre-AstraSim failure. Steal it on day one regardless of which design wins.
- **From C:** cutting the emitter over first by lowering from *unchanged* legacy graphs, so new-emitter equivalence is tested against bit-identical inputs and emitter risk is fully decoupled from builder risk — the single best de-risking move of the three, and it composes with either A's or B's end state.
